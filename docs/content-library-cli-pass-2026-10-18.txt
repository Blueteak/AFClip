Content Library CLI workflow observations, 2026-10-18

Scope: promote all 13 Inbox sources and make a rough annotation pass in the live default catalog. Existing source files and project edit timing stay in place.

Measured so far
- Atomic promotion of 13 sources: 136 ms including CLI process startup.
- Five 256-bin waveform requests: 173-251 ms each including CLI startup.
- First video preparation: 23.5 seconds; second completed 65.7 seconds after enqueue, including waiting for the first.

Optimization candidates
1. Separate lightweight review jobs from expensive preparation. The single FIFO queue held all eight contact sheets behind thirteen full preparation jobs. Deferred queued preparation and requeued it after sheets. Add priority or a separate bounded artifact worker.
2. Offer prepare --level index|preview. Exact range creation requires a frame index, while the current command also creates seek proxies and decoded audio. Agents should be able to annotate as soon as indexing finishes.
3. Add compact search/overview responses or --fields. Search embeds raw ffprobe streams and format metadata for every result; overview includes historical jobs and history. Initial discovery generated roughly 77k tokens across overview/search. IDs, revisions, kind, duration, folder, availability, and preparation state should be the default agent summary; inspect can carry full metadata.
4. Make Inbox filtering explicit in help. search --inbox includes Inbox alongside ordinary library items; search --folder inbox is Inbox-only. Prefer --include-inbox for the former, and reject unsupported/ambiguous flags.
5. Add command schema/help per operation. apply batches work well, but agents currently read source to discover fields, revision increments, and annotationTracks. Document batch return IDs/revisions and dependent operations on the same asset.
6. Contact sheets need frame timestamps and source labels in either the image or a returned frame manifest. Current sheets contain no timestamps, making rough selections possible but exact event localization harder.
7. Add a waveform summary with peak timestamp, activity bounds and source sample rate. Current waveforms use 48 kHz decoded data while source ranges may require 44.1 kHz. Return both rates explicitly to prevent incorrect sample-boundary conversions.
8. Progress/wait should report queue position, current phase, elapsed time, and distinguish accepted from complete. --wait currently polls silently every 250 ms and top-level ok remains true when a job fails, although process exit is nonzero.

Audio review uses filenames and decoded waveform data, not listening. Music windows are provisional editorial windows, not verified musical phrases.

Implementation follow-up, 2026-10-18
- Implemented queued-job priorities, index-only preparation, compact CLI search/overview and field selection, explicit Inbox flags, per-command schema/help, measured contact-sheet frame manifests, waveform summaries with both sample rates, and structured job progress/completion/failure/timeout reporting.
- Direct API/GUI search and overview retain full responses by default. CLI users can use --full. Existing --inbox CLI calls now fail with migration instructions.
- Thirteen disposable integration checks passed, covering filtering, parsing/schema, atomic revision ordering, compact/full compatibility, field projection, silence, index-only ranges, waveform timing/rates, cached contact-sheet manifest, preview preparation/progress, queue order, job failure, and timeout behavior. Test programs, fixtures and catalogs were removed after verification.
- Generated fixture search: 1,254 bytes compact versus 9,223 bytes full, about 86% less output. Overview: 2,310 versus 3,810 bytes.
- Separate cold catalogs on Boss_Beams_1.mp4, 12.6 seconds of 2560x1440 gameplay: index-only 11.9 seconds / 203,699 cache bytes; full preview 14.4 seconds / 2,630,929 bytes. One run per mode, including CLI waiting overhead; not a broad throughput benchmark.
- Priority scheduling does not interrupt active work. An artifact still waits for the currently running job. Full video decoding for an exact frame index remains the largest preparation cost in this sample.
